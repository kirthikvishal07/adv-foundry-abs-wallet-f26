Where does the magic value come from?

ACCOUNT_VALIDATION_SUCCESS_MAGIC is not generated from the transaction at runtime. It is a compile-time alias for the ABI selector of the validation function. The account returns that marker to tell the zkSync bootloader that validation succeeded.

ACCOUNT_VALIDATION_SUCCESS_MAGIC=IAccount.validateTransaction.selector→4-byte selector

Runtime path: transaction to return value

01 · CALLER

Bootloader calls account

validateTransaction(...) is external and gated by requiredFromBootLoader. Other callers revert before validation.

02 · NONCE

Advance expected nonce

_validateTransaction calls NonceHolder's incrementMinNonceIfEquals(transaction.nonce) through a system call. A mismatch/revert stops the flow.

03 · BALANCE

Check funds

Without a paymaster: value + max fee × gas limit. With a paymaster: value only. Insufficient balance reverts.

04 · SIGNATURE

Recover signer

MemoryTransactionHelper.encodeHash hashes transaction fields. ECDSA.recover recovers the address from that hash and signature.

↓ compare recovered signer with owner()

Owner signed ✓

isValidSigner == true → assign magic = ACCOUNT_VALIDATION_SUCCESS_MAGIC → return the selector to the bootloader.

Different signer

isValidSigner == false → assign magic = bytes4(0) → return zero, not the success marker.

Definitions and population point

Constant · IAccount.sol

bytes4 constant ACCOUNT_VALIDATION_SUCCESS_MAGIC =
    IAccount.validateTransaction.selector;

Assignment · ZkMinimalAccount.sol

bool isValidSigner = signer == owner();
if (isValidSigner) {
    magic = ACCOUNT_VALIDATION_SUCCESS_MAGIC;
} else {
    magic = bytes4(0);
}
return magic;

Test confirms the successful branch

testZkValidateTransaction builds a type-113 transaction, signs MemoryTransactionHelper.encodeHash(transaction) using the owner's test key, calls validation as BOOTLOADER_FORMAL_ADDRESS, then asserts the returned magic equals the imported constant.

What happens after the marker?

VALIDATION

Bootloader checks marker

It is a protocol handshake for successful validation, not the transaction hash or signature.

PAYMENT

Fee phase

Separate payForTransaction sends max fee × gas limit to the bootloader; failure reverts.

EXECUTION

Run the transaction

Later executeTransaction is callable by bootloader or owner and makes the target call.

OUTSIDE ENTRY

Validate, then execute

executeTransactionFromOutside runs both internally and does not expose this marker as its return.
