💡 Why does zkSync use a "Magic Value" instead of a boolean (true / false)?

1. Prevents Accidental Returns

In EVM memory, empty/uninitialized memory defaults to 0, and standard fallback handlers often return 1 (true). A specific 4-byte selector (0x2720d20d) cannot be faked or returned by accident.

2. Follows EIP-1271 Standard

Similar to how isValidSignature in EIP-1271 returns 0x1626ba7e, zkSync requires smart accounts to return their own function selector to explicitly prove adherence to the IAccount interface.

3. What is the Exact Value?

IAccount.validateTransaction.selector is the first 4 bytes of keccak256("validateTransaction(bytes32,bytes32,(...))"):
0x2720d20d
